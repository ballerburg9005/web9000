## P0 — architectural and security blockers

- [ ] **Legacy raw index storage hardening / migration and peer DoS.** `signed-access-controller.js` now enforces signed-event validity at OrbitDB `canAppend` in a distinct, opt-in `web9000-signed-v1` index. Two real Helia/OrbitDB peers confirmed direct malformed, tampered and oversized entries are rejected while unrelated valid signers/any namespace can publish. Old `IPFSAccessController({write:['*']})` indexes still physically accept invalid records despite Replica rejecting them; new signed peers require their own data directory, with a persistent mode/address binding to prevent accidental changes at restart. **Implemented 2026-11-19:** a tested, offline, opt-in [migration runbook](RAW-INDEX-MIGRATION.md) and CLI plan/copy/resume accepts a manually approved source snapshot, copies only original verified signed events, verifies destination IDs, and never cuts over automatically. **Still open:** cross-peer proof of completeness, continuous dual-write/catch-up, voluntary discovery of the new index, side-by-side rollout/rollback and operator resource limits. Also test unbounded network/CPU/storage amplification before declaring protection against all DoS.
- [ ] **Actual qualified network admission.** Real independent Stake4Karma on-chain verification and independently auditable earned karma. Separate curator index exists, but the test peer explicitly accepts *zero* qualifications; a local numeric simulation is NOT protection. Bind stake proof to exact wallet/public key, finalized chain state, coin/value, sufficient current remaining lock, resale/identity-farming throttles, appealable earned-credit history, and verifier independent of curator. `v2/network/qualified-index.js`, `node-peer.mjs`, `v2/core/anti-spam.js`.
- [ ] **Complete multi-transport media serving refusal / safe disposal.** **Mitigated 2026-11-19 for the Helia Bitswap transport**: `media-bitswap-policy.mjs` wraps only outbound Bitswap reads, dynamically checks this operator's manifest and quarantine policy, includes UnixFS descendants, refuses unknown/raw orphan chunks and fails closed on unreadable policy. Real two-peer Bitswap tests verified raw image and chunk refusal, reversible recovery, and simultaneous OrbitDB metadata delivery. This is a *local operator policy*, not network-wide censorship. **Still open:** other transfer protocols/transports, provider announcements, prior downstream copies, blocks cached elsewhere, in-flight race windows, safe physical deletion/GC, secure ingest, scanner/compliance review, latency and abuse budgets. A manifest-unknown raw/DAG-PB block is withheld by design; test all future metadata codecs against this guard. `v2/network/media-bitswap-policy.mjs`, `node-peer.mjs`.
- [ ] **Storage abuse and safe ingestion.** Prototype gateway allows unauthenticated cross-origin uploads subject to per-IP per-day caps and magic-byte checks, not robust media decode/type validation, virus/CSAM screening, authenticated resource budgets, per-user quota economics or DNS/IP/threat-model audits. UnixFS DAG creation before quarantine may leave orphaned blocks. Protect operators without imposing global censorship. `media-node.mjs`, `mirror-media.mjs`.
- [ ] **Independent temporal and governance evidence.** Signed event timestamps are *author-supplied*, not witnessed time. Disconnected replicas may have missing/future/backdated ballots; 7/14-day policy is a local observation, not globally final consensus. Need multi-peer signed checkpoints/attestations, late-vote challenge windows, explicit evidence completeness limits and fork/finality semantics. `v2/core/governance.js`.
- [ ] **Signing-key security, recovery and privacy.** Default browser key can be exported for password-protected backup, but untrusted hosted application JavaScript can potentially use/steal it. Design user-controlled origin-independent signing (Nostr NIP-46-like signer or hardware/OS signer, with explicit per-origin/per-event permissions); key rotation/compromise evidence; safe recovery of group votes; encrypted groups/DMs only with formally reviewed authenticated encryption. A site URL is not a trusted identity guardian. `v2/core/events.js`, `identity-backup.js`, `v2/classic.js`.
- [ ] **Public release threat review.** Cross-peer censorship/eclipsing, spam and resource exhaustion, targeted suppression and false flags, privacy/social graph leakage, media compliance, curator capture, multi-origin/hosted-script attacks, real-world law and content safety. Document assumptions and independent appeal paths before declaring production readiness.

## P1 — missing core functions

- [ ] **Group vote initiation based on *earned, verifiable karma* AND the *age of approved membership*.** This is the owner's latest preference (2026-11-19). An account following/subscribing is not a member; a member may still lack eligibility to *propose*. Actual group-recognized approval/anti-karma and member acceptance can be reviewed through explicit signed votes visible below posts. Frozen verified score at a predeclared observation point; no mock scores as authority. Configurable quorum-backed charter evolution with group size/activity, anti-capture floors, and appeal. The current code only checks whether the proposal signer is a ratified member.
- [ ] **Approved membership lifecycle, inactivity and recovery.** Signed applications, member-issued karma/anti-karma, transparent admission ballots, waiting periods, suspensions with due process, revocable/expiring proxies, voluntary leaves, lost keys, dormant groups and protected reconstitution. Inactivity must not silently revoke democratic rights or enable takeover.
- [ ] **Nested/federated groups with *scoped* specialized authority.** The prototype has `delegate`, `undelegate` and simple reviewer inheritance but **no** jurisdiction/topic scopes, time limits, branch pinning, conflict resolution, provenance, specialized screening evidence, challenge/appeal obligations, multi-parent policy or complete cycle/conflict semantics. Delegation must remain voluntary per reader/peer; never a namespace owner.
- [ ] **Independent multidimensional group review and reputation (owner corrected 2026-11-19).** **Partially implemented:** signed `content-rating` (0–6 age suitability + four 0–5 radar scores + special public-interest alert), signed individual `group-rating`, `reviewer-conduct` and `reviewer-candidacy` events, group-trust and reviewer-audit UI, ratified-group-only authority projection, versioned reader-local 2/5/2 blur/hide/counter-rating thresholds **off by default**, a readable post spider chart, and member-voted reviewer appointment/removal proposals. Groups **do their own content assessments**; there is NO other-group-decision challenge or mandatory intergroup consensus. **Open:** proven reviewer accuracy, trust weighting/scoring and Sybil barriers, noncoercive possible reputation spillover, helpful public-interest ranking without spam, term/election details, group size/activity adaptation, automated suggested tuning with user migration/rollback, verified peer completeness, appeal and independent expert media review. Default age/political values are provisional, never network-wide rulings. See [COMPOSABLE-MODERATION.md](./COMPOSABLE-MODERATION.md).
- [ ] **Review/appeal/false-flag adjudication and anti-karma auditing.** Labels, votes and reports exist; independently signed, appealable abuse findings and proportional sanction scheduling do not. Implement reviewer scope, reputation/accountability, evidence, public reversals, specialized content safety, review-group demotion, and transparent local suppression reasoning.
- [ ] **Metadata replication scopes and efficient anti-entropy.** **Partial 2026-11-19:** the reader can now explicitly choose one or more public namespaces in the compact Join Network dialog, persist/reconnect the selection, and scope actual WebSocket history and live events. The browser ALSO rejects out-of-scope signed records even from deliberately misbehaving bridges (unit and four-origin Chromium tests). Default `['*']` remains for old users, and previous local records are retained. **2026-11-19 backend follow-up:** `scoped-event-catalog.mjs` now incrementally indexes signed IDs per namespace and serves bounded pages without rescanning/sorting the full replica. Each subscribe has a fixed **local observation revision** to stabilize a history walk while new signed events arrive as live notifications; tests cover 9,000 local IDs, changed records during paging, the true WebSocket bridge and peer replay. **Still open:** per-author/outbox/member interest queries, signed/witnessed checkpoints, NIP-77-like cross-peer set reconciliation, pruning, bounded repair against omission/missing history, and independent peer discovery. A locally frozen revision only describes this peer's observed records, **never** network-wide completeness; limits remain 1,000 pages × 32 IDs. Subscribed space names are visible to the peer, not a private-group protocol. Keep all namespaces publicly writable.
- [ ] **Independent peer discovery / transport robustness.** Manual WebSocket bridge URLs, static `peers.json`, manual OrbitDB addresses and libp2p peer multiaddrs. Not true peer-independent discovery on any domain, browser-native libp2p/WebRTC, redundant independent bootstrap, robust NAT traversal or portable multi-device outbox.
- [ ] **Real media availability/integrity and selective volunteer replication.** Explicit operator-to-operator mirroring and signed provider claims exist. Browser does not validate arbitrary UnixFS CID against downloaded bytes and cannot opt in to full media mirroring with quota/bandwidth/scope/blacklist controls. Native IPFS block-level discovery/failover, durable media availability and constrained background replication are missing. Keep default browser metadata-only.
- [ ] **Cross-origin social list portability.** Add friend/foe currently stored only in that browser's local IndexedDB. Explicitly designed, possibly encrypted, owner-signed selective syncing/backup and independently validated reputation interpretation remain open. Preserve privacy; never silently publish the social graph.
- [ ] **Ingest/filter/sort at scale.** Backend default bridge scans the whole in-memory replica to serve wildcard/id-cursor pages and only has per-client rate limits on test deployments. Need bounded query indexes, limits on replay/invalid records, storage budgets, recovery from missed IDs, and genuinely independent shard replication without losing user's raw audit view.
- [ ] **Portability/interoperability layer.** WEB9000 Ed25519/v1 events are **not** Nostr Schnorr/secp256k1 events. Consider a separately signed dual-protocol bridge or generic NIP labels/relay reference mappings; do not silently reinterpret Nostr events as native WEB9000 group authority. Backwards-compatible event evolution requires signed and tested migrations.

More than a cosmetic issue if a suggestion becomes transport/media authority.
- [ ] **Better provider discovery and failure transparency.** Signed media-provider claims are unverified, may be stale, and only reorder preapproved gateways; need signed/monitored liveness, refusal/expiry evidence, independent error reporting and avoid unnecessary requests.
- [ ] **Share/discover posts, archive/export/federated backups** beyond current raw debug JSON and encrypted identity backups; portable content bundles and approachable peer setup.
- [ ] **Accessible mobile and desktop regression, network simulation, resource caps and profile workflows.** Continue real headless browser tests with multiple origins and peer restarts, layout focus, queued offline publication, audio/video seeks, timestamp conflict and adversarial invalid-signature cases.

## DESIGN — intentionally NOT settled

- [ ] **Which group activities earn/lose karma?** Anti-karma strength, cooldown, score history, sybil rings, reciprocity, bribery/collusion, forged evidence, moderation misuse, member standing and appeals. User expects **fine-tuning later**, not one hard-coded global formula.
- [ ] **How are initiative thresholds scaled?** Eligible member count, *actual* group activity, tenure since signed ratification, independent karma, member type, urgency, constitution vs ordinary motions, veto/challenge conditions, decay. For low activity avoid all-members deadlock **without** letting tiny minorities take over.
- [ ] **How to handle group hierarchies, shared rules, nested legal/safety screening, and conflicting specializations?** Parent/child scope, lifetime, source authorizations, accountability, transparency, appeals, jurisdiction, fork, override, snapshot version and cycle handling are not approved yet.
- [ ] **How friend/foe labels affect credibility.** Current action is explicitly reversible local preference with **zero** governance weight and no broadcast; decide whether public, encrypted, mutual, transitive or purely personal only after privacy/abuse review.
- [ ] **How censorship-resistance and lawful safety coexist.** A voluntary peer may lawfully refuse and unpin; no global or irrevocable coercive moderator; specialized expert findings must be independently reviewable and narrowly scoped.
- [ ] **Whether to adopt Nostr wire interoperability or only selected techniques.** See [NOSTR-RESEARCH.md](./NOSTR-RESEARCH.md). Avoid adopting NIP-29 relay-owned group semantics or NIP-01 'keep latest only' for immutable governance proof.
