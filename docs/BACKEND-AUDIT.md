# WEB9000 backend audit — actual implementation versus owner vision

**Audited 2026-11-19 on `main` (owner-requested fast-forward of old development branch).** This is a code-based design audit, **not** a completed third-party security assessment. Paths/line anchors describe the audited source revision around `b23de76`; subsequent edits may shift numbers. All findings distinguish **implemented behavior**, **confirmed discrepancy**, **potential weakness requiring reproduction**, **provisional unapproved choice**, and **correctly implemented behavior**.

Owner's controlling principles are in [PRODUCT-REQUIREMENTS.md](./PRODUCT-REQUIREMENTS.md) and [CHAT-DECISIONS.md](./CHAT-DECISIONS.md). Experimental code does **not** automatically imply the owner approved its tradeoffs. [OPEN-ISSUES.md](./OPEN-ISSUES.md) is the priority list.

## Features that **match** the user vision and should NOT be undone

- Arbitrary namespace publishing is deliberately free of a global write ACL. A reader/peer may reject hosting/displaying a record, never invalidate the signature or require consent from whoever first registered a name. `events.js`, `Replica.ingest`, `orbit-index.js`, local `policy.js`.
- Multiple independent cryptographic signers, signed group proposals/votes, locally selected forks and a portable proof of an **included** quorum-ratified branch, rather than relay-admin ownership. `governance.js`, `group-proof.js`.
- Immutable author revisions and withdrawals are new signed events, not overwriting original records across all willing mirrors. `lifecycle.js`.
- Signed text records carry IPFS content references, but browsers do not automatically pin unknown media and specialist nodes choose what to store; rich file cap is **10 MiB** not decimal MB. `media-node.mjs`, `media-discovery.js`.
- Moderation labels are signed claims and curatorial choices applied locally by opted-in readers. A site's preferred author is a presentation option, not network publication authority. `core/policy.js`.
- Test karma is visibly simulated and not used as validated governance or live qualified-index admission. A separate qualified OrbitDB namespace exists with no false claims of verified users.
- Peer indexes can be distinct, users can choose gateways/peers, private signing identity can be password-backed up, and browser tests demonstrate real cross-site signed interactions.

## Audited and **ruled out** (important correction)

I initially suspected a `set-quorum {numerator:0, denominator:0}` path could result in a `NaN` threshold. I attempted to sign that amendment in the live code and `validatePayload` **rejected it** with `Invalid quorum`. The code requires `numerator>=1` and `numerator<=denominator`; those jointly imply `denominator>=1`, even though it does not state this in a separate clause. **Do not list zero-quorum as a confirmed bug or patch it under a false exploit claim.**

## Decisions the implementation made **without explicit sign-off**

1. The default `timed-v1` choice in the new-group form, with fixed 7-day advisory and metadata deadlines, 14-day constitutional deadlines, one-third advisory turnout floor and majority/two-thirds constitutional signing. These are **provisional engineering defaults**, not an approved final political model; owner prefers proposal **eligibility by earned karma + approved-member tenure**. Keep existing signed records backward compatible when designing better rules.
2. Same-origin demo auto-connect and default enabled optional `owner` presentation preference. These are visible but may steer what users see. Require owner review before production.
3. Separate origin-local friend/foe labels without public signed synchronization. This is intentionally conservative for privacy, but unresolved how portable identity reputation should work.
4. Browser event and transport budgets (max 25,000 local verified events, at most eight bridges, 32-event pages), raw index write-all, and single selected default media gateway. These are prototype sizing choices, **not** proven safe or scalable decisions.
5. Endorsed moderator label weighting and group vote invariants are applied client-side; no institution/authority or legal process is proven by a signed identity alone.
6. Group-aware reviewer policy currently applies group membership only through manually followed/signed groups; it lacks real juristic/specialized code paths and does **not** automatically own/serve a public namespace.
7. Static website scripts directly operate origin-local identity keys. That was an expedient UX choice, not a reviewed trust separation model.

## Independent multi-axis review and group-accountability implementation audit (2026-11-19)

**Scope:** independent signed opinions, **NOT** neutral truth, lawful classification, universal child moderation, globally approved group ratings or elections finalized with external timestamps. `content-rating` carries a signed post ID, 0–6 age/suitability tier, four integer 0–5 axes, optional special public-interest alert and optional group claim. Validators reject malformed/unknown rating axes, attempts to insert attributes referencing another group's decision, and tampering breaks Ed25519 verification. Signatures come from ordinary user keys; they are **not inherently Sybil-resistant**.

`assessContentRatings` locally selects the latest signed rating per signer/target, admits only explicitly approved reader signer keys or ratified reviewer keys of voluntarily subscribed group branches for **automatic visual effects**, and never gives authority to a self-asserted group ID. Rules are versioned, locally persisted, initially inactive and configurable. Age 18+ example: 2 qualifying votes blur, 5 hide; 2 credible low-age dissent signals clear even against 10 high-age group ratings. These counts are examples **not scientifically calibrated or approved network rules**, and unlike legal storage policy never affect global post existence. A locally HIDDEN image/audio/video preview is not fetched until reader reveals; a blurred image may already download because it must render blurry. A local reveal does not rewrite any signed record.

The spider chart shows recognized content values; popularity remains separate. The special public-interest alert is a constrained advisory boolean, requiring multiple recognized opinions plus elevated urgency/intellectual score before a text-first visual hint, but has **no automatic spam admission or global notification privileges**. Reader-selected group and individual reputation may still be manipulated by coordinated keys, compromised client JavaScript or withheld histories; presentation scoring is not a reliable legal, demographic or political classification.

Signed `group-rating` are outside opinions (deduped per signer) shown to willing users, **not automatically inherited penalties across members**. `reviewer-candidacy` lets someone volunteer with zero immediate permissions. Group reviewer appointment or removal still requires ratified charter proposals/member votes; reviewer profile audit records signed ratings/labels and signed third-party `reviewer-conduct` opinions. A tiny badge appears only for a group reviewer ratified by a group that the current reader follows. **Still open:** independent correctness/reviewer reputation evidence, actionable appeals, sybil-resistant selection/weights, adaptive threshold *suggestions* and migration UI, validated epoch/term expiry, independent peer evidence completeness, scalable scope-specific indexes for rating aggregation, legally safe byte ingestion/GC and contributor privacy.


### Compact spider UI and independent public-interest report (2026-11-19)

The previous in-article \`content-rating-panel\` and duplicated range inputs were replaced with a single 324-pixel-or-less viewport-clamped \`spider-popup\` entered via the **🕸 button immediately after the signed popularity score**. Its five pointer-captured radial handles correspond to age 0–6 and the existing four 0–5 dimensions; they also respond to keyboard arrows/Home/End and have descriptive ARIA values and visible level descriptions. Ordinary article layout retains no extra panel when closed. Popup dismissal is by Escape, outside pointer or its close/cancel button; it must not be dropped merely because async signed-record synchronization rebuilds the selected post.

\`⚑ Report\` now includes a special \`public-interest-censorship-pressure\` label, published independently of the content-rating event. \`content-ratings.js\` counts only reader-trusted/reviewer-ratified distinct signers for alert recommendations, merging historical \`content-rating.publicInterestAlert\` and the new labeled event without doubling one author. **A bare democratic-interest flag contributes NO age/safety tier or intellectual/controversy number**, does not alter normal popularity and cannot unilaterally bypass reader spam admission. Older signed rating events are still valid. UI recording, mobile overflow, pointer drag, keyboard focus, age-hidden media reveal and independent report publication are covered by cross-origin browser testing. Any missing peer history or hostile group claims remain untrusted.


### Cross-browser spider background trust separation (2026-11-19)

**Confirmed UI bug:** the old gray \`spider-community\` polygon used the strict \`assessContentRatings().qualifiedCount\` aggregation, so a valid signed rating published from another browser/account usually had no visible gray reference until its author was individually trusted. That was an accidental conflation of informational comparisons with local filtering authority.

**Fixed:** \`summarizeSpiderBackground\` now builds per-axis medians from each **other signer**'s latest validated \`content-rating\` event observed in the local signed replica (excluding the viewer's signing key). No default group credentials are required for this informational shape. A future \`approved-authors\` selection hook accepts a caller-supplied set of **independently verified** keys; currently it is not connected to a completed trusted-federation graph. The graphic labels its **observed signer count**, not independently proven humans or globally complete network history, and incoming signed ratings update it **while the popup is open**, without losing a local unsent pink rating. The separate strict \`assessContentRatings\` aggregation still alone controls reader-selected blur/hide and public-interest text-first hints; the former 2/5/2 safeguards are unchanged. Distinct Ed25519 keys are not Sybil-resistant humans, and compromised/disconnected peers can omit legitimate ratings. Unit tests confirm signature dedupe, self exclusion, mean-of-middle median and trust separation. Real multi-origin Chromium test opens two **isolated browser profiles**, publishes genuine independent signed ratings through the peer, and checks the receiving gray shape updates live while the reader's pink values stay fixed.

### Initial independent-peer reconciliation audit (2026-11-19)

The optional WebSocket inventory protocol now exposes signed-event ID-set fingerprints scoped to the explicitly subscribed public namespaces, using the existing local frozen snapshot. The new operator-only two-peer comparison tool reports differences, and only when explicitly instructed does it fetch original signed event envelopes, verify them independently and ask the receiving peer to publish them. At no point does it claim network-wide completeness, grant a group namespace access control, or mirror IPFS media by default. The bridge validates prefixes, request sizes, cursor ranges and per-ID subscription eligibility. Real two-bridge tests validate differences, out-of-scope fetch refusal, snapshot freezing and voluntary repair.

**Important unresolved risk:** A dishonest peer can consistently lie about its inventory, omit selected valid signed posts, or refuse to admit a repaired record. The SHA-256 range digest is a **peer-asserted local observation**, not a signature witnessed by other peers, a signed transparency checkpoint, or proof of nonexistence. The current CLI has strict difference budgets and slows requests to fit the test service, but is not a scalable production anti-entropy engine. Do not use it to assign malicious-censorship guilt or make mandatory trust decisions. See [PEER-RECONCILIATION.md](PEER-RECONCILIATION.md).

### Browser read-only peer inventories and larger text-first grid (2026-11-19)

The header-only Debug console has a *collapsed* two-peer comparison control listing only the reader's explicitly selected WebSocket peers. Clicking Compare opens temporary WebSockets, subscribes to the reader's chosen namespace scopes, and queries inventory fingerprints and (when <=256 IDs per peer) bounded ID pages. The client checks per-page sorting and each peer-reported digest, but a Byzantine peer can return a consistent incomplete set; equal reports never prove network-wide completeness. Comparison never publishes, fetches media or authorizes other peers. Unit/integration tests exercise two distinct bridges and a deliberately dishonest inventory server.

The inventory-v1 digest serialization retains its originally deployed two-literal-byte backslash-plus-n separator per signed ID, rather than introducing a wire-incompatible LF change. Read-only clients must match that exact byte serialization. No signed event schema or original record changed. The separate operator CLI remains the sole explicit repair mechanism.

The owner also requested one larger type step and an H2-like vertical breathing area inside actual Classic grid text previews, not just Mixed. CSS now enlarges text without resizing media tiles; computed browser geometry is covered by Chromium.


### IPFS tier feasibility and remaining serving isolation (2026-11-19)

Real local experiments found that 100 separately opened LevelDB media blockstores under one Helia/libp2p identity hold ~105 MiB of synthetic media with little storage-count overhead, while 100 separate local Helia network identities can independently hold it. A genuine 100-source Bitswap exercise streamed 101/101 CID objects to an independent reader under WEB9000 outbound media quarantine policy. **Neither architecture yet establishes hard spam isolation:** the one-node storage experiment has NO shared-node tier-aware block-serving adapter; the 100-node trial uses one Node.js process and lacks per-source OS-level CPU/RAM or bandwidth limits, and did not measure adversarial saturation. Post-close TLSSocket handles remain and need dedicated lifecycle investigation. Detailed evidence and commands: docs/IPFS-TIER-BENCHMARK-2026-11-19.md.


### Adaptive physical OrbitDB segmentation sandbox (2026-11-19)

An isolated operator-controlled module creates physically independent OrbitDB event-index logs, curatorial write ACLs and bounded, source-aggregated admission before Ed25519 verification and log append. Automatic split/shrink only affects the destinations for NEW records; prior shard addresses are still readable and not migrated. Real tests show unapproved direct OrbitDB writers cannot bypass a curator's shard ACL, while legitimate signed authors remain free to publish to any unrelated willing index. Signed raw popularity and a mock stake balance are NOT accepted as privileged replication credentials. A separately budgeted/cached verifier interface exists; only a named independent evidence callback could authorize a time-limited sponsored/established local pool. A soft in-process queue and local rate cap are NOT hard system failure isolation; upstream libp2p/HTTP preparse caps, portable discovery manifest, true physical GC, OS cgroups and real reputation proof are NOT implemented. Inherited geolocation/ASN/last-hop source observations are local and not author-origin proofs. Never advertise this as a deployed spam solution. Full review: docs/ADAPTIVE-SEGMENTATION.md.


### 2026-11-19 source-failure compartments and signed historical shard manifest

An optional prototype can place operator-observed country/ASN/coarse IP prefix/VPN/hosting/relay cohorts into separate locally capped physical OrbitDB compartments, including different entry and independently attested sponsored/established boxes. This is resource separation, not a finding of misconduct. A local quota failure can recover next window; no universal country block is enforced. Client-supplied network metadata must never be treated as a trusted observation and libp2p source IP may identify only the relay. The current test doesn't demonstrate OS worker isolation, pre-OrbitDB network/fetch limits, or hard disk garbage collection.

The locally stored operator-signed append-only historical shard directory prevents accidental re-creation at a different OrbitDB address on restart, and independently verifies retained address mappings, revision signatures and pinned rollback checkpoints. Real OrbitDB test confirms historical signed events survive reopening. A single curator's signed list does not prove global completeness; independent discovery and audience-pinned operator identity are missing. Source pseudonym salt and signing credentials must be backed up securely for reliable long-term routing.


### 2026-11-20 selective priority subscriptions and cgroup-separated worker test

The opt-in priority-shard-loader.mjs restores the operator-pinned, Ed25519-verified highest-priority physical OrbitDB logs first and reserves an entry slot. A real fixture of 100 independently signed OrbitDB indices warmed 20 active subscriptions in 0.480s (~153.50 MiB RSS) versus 100 in 2.492s (~158.11 MiB RSS). Deactivated indexes remain in the directory; reads to dormant indexes can activate them under a bounded cap. This is per-reader voluntary resource allocation, not global governance or correctness proof.

The sandbox isolated-tier-worker.mjs hosts one actual Helia/OrbitDB index in its own OS worker process with small bounded signed event intake. A process-crash test force-killed entry after invalid-packet flood while protected author-allowlisted worker remained live; two separate Docker cgroups further enforced 0.25 CPU, 256 MiB and PIDs 64 each and protected health checks succeeded during entry CPU saturation and after stopping entry. The lab whitelist does not implement real reputation, Stake4Karma or invitation qualification. The worker listens to loopback only, and the Docker trial deliberately used --network none: cannot establish public-facing flood isolation. A trusted cheap prefetch gateway, OS worker pool scheduler, actual media bandwidth/IOPS caps and append-only garbage collection remain unimplemented.


### 2026-11-20 actual bounded HTTP ingress, per-lane process, pinned operator receipt

The isolated test ingress (bounded-ingress.mjs) now limits HTTP body bytes, signed-proof verifier concurrency, source cohorts, and per-tier pressure *before* expensive Helia/OrbitDB append work. The independently signed operator-issued short-lived ingress-capability is checked on both gateway and independently running protected worker and bound to the original author, who must still independently sign the original record. Client X-Forwarded-For, metadata-country, self-claimed karma and tier are ignored as authority. Two distinct gateway executables (entry-only/protected-only) can survive each other's process failure; tests with independently running Helia workers pass. This still lacks a cgroup-protected public HTTP/L4 ingress deployment, real Stake4Karma/vouch verification, libp2p prefetch control and GC, and should not be mistaken for a complete network DoS shield. Owner selected 20 new physical databases; maxShards=20 is now enforced; previous history stays signed/portable.


### 2026-11-20 real HTTP+cgroup sandbox and genuine operator-pinned voluntary evidence

Standalone test-only Nginx entry/protected/proof edges, individually CPU/RAM/PID-limited workers and gateways, and isolated proof issuer were exercised in an 8-container Docker Compose stack with only host-loopback test listeners. 100 adversarial invalid entry messages were declined (96 429 / four 422), with valid signed sponsored publication continuing after the entry edge container was stopped. No live peer or production proxy was altered, and temporary signed-key/test blocks were cleaned up. The original-signed-record cold-start worker test passes. A 0600-only operator issuer can grant short-lived subject-bound physical-resource credentials *only* after independently signed accepted invitation chain from locally trusted roots or signed quorum group membership on locally pinned charter branch. Stake4Karma v0.5 SDK is separately vendored at immutable upstream commit cce170d99f105b8f7a67d7102586c64c70eff9e3, with MIT license. Its optional Base Sepolia **testnet-only** proof checks nonce, signature, bytecode hash, chain, active escrow and min test ETH against a mocked provider in tests, not a real deployed chain. Do not treat user-supplied balance, self-asserted governance, or unknown contract address as verified stake. Important source limitation: Nginx can see immediate remote IP; gateway sees Nginx loopback and no actual trusted per-origin VPN/ASN/country classifier is yet wired across layers. See docs/INGRESS-PROOF-EDGE-2026-11-20.md.

### 2026-11-20 browser-signed network-source classification and pre-append grouping

Optional browser-bridge source observer with private 0600 Ed25519 identity and signed operator-provided IPv4/IPv6 CIDR geolocation/ASN/network-kind list classifies the ACTUAL socket hop; X-Real-IP is valid only with one explicitly pinned proxy socket. Local per-class coarse /24 and /48 attempt quotas are charged BEFORE expensive signed-envelope verification. The accepted event ID can be accompanied by a short-lived signed source-hop receipt (country/ASN/type but never raw IP), and browser-mesh independently verifies the locally pinned signer and the updated source-feed digest/revision with WebCrypto. The browser can defer exhausted low-priority VPN history without disconnecting unrelated live categories. Source list updates are signed and delivered through existing WebSocket sessions; this is an opt-in subscriber resource decision, NOT universal location/identity evidence. The ordinary live node remains in old mode; public network geo feed, authenticated proxy chain, true browser-native libp2p and storage GC are still absent.
